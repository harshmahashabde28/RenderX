A simple blueprint for a 3D wireframe rendering engine using Python and Pygame.
1. What RenderX will do
RenderX will display a cube and a pyramid made of points and connecting lines. The user
can rotate, move and resize each object using the keyboard.
The program calculates how a 3D object should appear on a flat screen, then uses Pygame
to draw it. The first version focuses on wireframes; textures, lighting and shadows are
outside its scope.

6. Data and database schema
The first version keeps shapes in Python lists or tuples, so it does not need a database. If
saved models are added later, SQLite can use this simple schema:
Table
Fields
Model
model_id (primary key), name
Vertex
model_id, vertex_index, x, y, z
Primary key: (model_id, vertex_index)
Edge
model_id, start_index, end_index
Primary key: (model_id, start_index, end_index)
One model has many vertices and edges. Each edge connects two vertices in the same model.
Model IDs link the tables; each endpoint references a vertex. Store each edge once, with start_index
< end_index.
7. Proposed project schedule
Time
Work to complete
Weeks 1-2

Weeks 3-4
Implement rotation, movement, scaling and 3D-to-2D projection.

This is an estimated eight-week plan. Adjust the dates to the college deadline.
8. Development and testing
Build one part at a time and test it before adding the next. Check that both shapes render
correctly, controls work smoothly, and closing the window exits properly. Reject points too
close to or behind the camera before projection.
Final deliverable: a working Python/Pygame application, two built-in shapes, source code
and a short setup-and-controls guide.
